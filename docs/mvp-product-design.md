# ExperimentLens MVP 产品设计文档

## 1. 产品概述

ExperimentLens 是一个面向计算实验场景的实验结果分析与排错 Agent。它帮助研究生和研究人员把分散的实验结果、配置和日志转化为可追溯的分析结论、排错假设和下一步实验计划。

MVP 聚焦机器学习与数据科学实验中最常见的场景：用户完成多组配置、多次 seed 的实验后，希望快速知道实验表现如何、结果是否可信、异常可能来自哪里，以及接下来最值得验证什么。

产品的一句话定位：

> 将实验结果、配置和日志转化为可信的异常解释与下一步实验计划。

## 2. 目标用户

### 2.1 核心用户

- 需要频繁开展计算实验的研究生。
- 从事机器学习、数据科学或相关研究工作的科研人员。
- 需要对模型、算法或参数进行对比验证的工程研究人员。

### 2.2 典型问题

- 实验组是否真的优于 baseline，而不是偶然波动？
- 为什么某一组实验表现明显下降或不稳定？
- 多个 seed 的结果差异是否在可接受范围内？
- 下一轮应该优先验证哪个假设？
- 如何把散落在表格、配置和日志中的信息整理成可分享的结论？

## 3. MVP 目标

MVP 需要完成一个清晰的用户闭环：

1. 用户导入实验结果、配置和日志。
2. Agent 识别实验结构，并由用户确认关键字段。
3. Agent 生成实验总览、对比结果和异常检查。
4. Agent 根据证据提出排错假设。
5. Agent 推荐成本较低、信息增益较高的下一轮验证实验。
6. 用户导出或分享分析报告。

MVP 的重点不是覆盖所有实验类型，而是验证用户是否愿意依赖 Agent 完成“结果理解—问题定位—下一步决策”这一过程。

## 4. 主要功能

### 4.1 实验数据导入与结构识别

支持导入：

- CSV、Excel 格式的实验结果表。
- JSON、YAML 格式的实验配置。
- TXT、JSONL 格式的运行日志。
- 用户填写的实验目标、核心指标和 baseline 信息。

Agent 自动识别实验编号、实验组、对照组、超参数、指标、seed、数据集、模型版本和运行状态。识别完成后，通过一次简短确认让用户修正错误映射。

### 4.2 实验结果总览

为当前实验生成统一概览，包括：

- 最优实验及其关键配置。
- 实验组相对 baseline 的变化。
- 指标的均值、标准差和置信区间。
- 不同 seed 的稳定性。
- 运行时间和资源消耗概况。
- 缺失、重复、失败或未完成的运行。

输出应同时包含图表和自然语言结论，避免只呈现原始统计结果。

### 4.3 Baseline 对比分析

用户可以指定一组实验作为 baseline。Agent 分析：

- 不同配置的性能提升或下降。
- 提升是否稳定，是否由少数异常运行造成。
- 性能、稳定性和计算成本之间的权衡。
- 当前实验数量是否足以支持结论。

首版统计能力以描述性统计、置信区间、效应量和常用显著性检验为主，不提供复杂因果推断。

### 4.4 异常检测

优先发现以下高频问题：

- 指标出现 NaN、突变或明显离群值。
- 不同 seed 之间波动过大。
- loss 不收敛、剧烈震荡或呈现过拟合趋势。
- 实验配置缺失、重复或不一致。
- 运行时间、显存或其他资源消耗异常。
- 不同实验可能使用了不同的数据或模型版本。

每个异常应指向具体实验、指标或日志片段，并说明判断依据。

### 4.5 排错假设生成

Agent 根据结果、配置和日志提出按优先级排序的候选原因。每个假设至少包含：

- 假设内容。
- 支持证据。
- 反对证据或当前不确定性。
- 置信度。
- 验证方法。

Agent 应明确区分事实、相关性和推测，避免把候选原因表述为已证实的因果结论。

### 4.6 下一轮实验建议

针对高优先级假设，Agent 给出可执行的最小验证实验，包括：

- 建议改变的变量。
- 需要保持不变的条件。
- 建议的运行次数或 seed 数量。
- 预期现象。
- 不同结果分别支持或否定什么假设。
- 实验优先级和大致成本。

目标是帮助用户用尽可能少的新增实验排除最多的不确定性。

### 4.7 对话式追问

用户可以围绕当前实验继续提问，例如：

- 为什么配置 B 的均值更高但不建议采用？
- 哪几个运行导致了方差增加？
- 如果只能再跑三次实验，应该怎么安排？
- 这个结论依赖哪些数据？

回答应继承当前实验上下文，并引用具体证据。

### 4.8 分析报告导出

生成可保存和分享的分析报告，包含：

- 实验目标和数据概况。
- 核心结果与图表。
- Baseline 对比。
- 异常项。
- 排错假设及证据。
- 下一步实验建议。
- 使用的数据文件、配置和运行编号。

## 5. 核心交互流程

```text
创建分析任务
    ↓
上传结果、配置与日志
    ↓
确认实验字段和 baseline
    ↓
查看实验总览与异常
    ↓
与 Agent 追问和排错
    ↓
生成下一轮实验计划
    ↓
导出分析报告
```

## 6. MVP 范围边界

第一版暂不包含：

- 自动修改代码或直接启动实验。
- 全自动超参数搜索。
- 论文搜索、复现与文献综述。
- 复杂因果推断。
- 实时监控大规模训练任务。
- 长期项目知识库和多人协作。
- 对湿实验等非计算实验场景的完整支持。
- 与所有实验平台的集成。

首版优先通过文件上传验证核心价值。Weights & Biases、MLflow、TensorBoard 等平台接入可根据用户反馈后续增加。

## 7. 产品原则

- **证据优先**：重要结论必须能追溯到原始结果、配置或日志。
- **不确定性透明**：明确说明数据不足、假设和置信度。
- **行动导向**：分析最终应转化为可执行的下一步实验。
- **用户可校正**：字段识别、baseline 和关键假设都允许用户修改。
- **低使用门槛**：用户无需预先整理成复杂的专用数据格式。

## 8. 成功指标

MVP 阶段重点观察：

- 从上传文件到获得第一个有效发现所需的时间。
- Agent 发现的异常被用户确认的比例。
- 排错建议被用户采纳的比例。
- 用户是否愿意上传第二批实验继续分析。
- 相比人工查看表格和日志节省的时间。
- 关键结论具有明确证据引用的比例。

## 9. 后续方向

在核心闭环得到验证后，可逐步扩展：

- 接入主流实验管理平台。
- 对训练过程进行实时监控和预警。
- 记录跨批次实验历史与研究决策。
- 自动生成实验配置或运行脚本。
- 支持图像、曲线等更多实验产物。
- 支持团队协作、评论和报告版本管理。
